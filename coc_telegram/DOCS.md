# Clash of Clans Telegram Bot (independent Home Assistant add-on)

This add-on does not alter or share settings with the Home Assistant smart-home Telegram bot.

## Installation

1. In Home Assistant **Settings → Apps → Install app → ⋮ → Repositories**, add `https://github.com/Beerlogger01/CoC_Telegramm`.
2. Refresh and select **Clash of Clans Telegram Bot**.
3. Enter `telegram_bot_token` (BotFather), `coc_token` (developer.clashofclans.com), and `coc_clan_tag` (including #).
4. Start the app and inspect its logs.
5. Add the bot as admin of a **private Telegram group** with invite and remove permissions. Use `/chatid` in the group and set `clan_group_id` in the app config.
6. Users bind with `/bind #PLAYER_TAG` in a private chat with the bot. Account verification, when enabled, requires the **player API token from game settings**, not the developer portal token.

## API and network

Clash of Clans developer keys must allow the Raspberry Pi's **public outgoing IP**. This add-on contains its own private API at `127.0.0.1:8000` **inside the container**, with no host ports. Redis and Docker Compose are not needed.

## Persistence

Player associations are stored in `/data/bindings.db` and survive restarts; backups are handled by the Supervisor. All credentials live in add-on configuration, never the Git repository.

## Images and updates

The version in `config.yaml` matches the tag on `ghcr.io/beerlogger01/coc-telegram`. The image must be **published and public** on GHCR before Home Assistant can install it. The GitHub Actions workflow publishes multi-architecture images after code is merged to `main` and tests pass. Pull requests run a build without publishing.

## War analytics

War snapshots are sampled locally every five minutes, including clan war league rounds. The bot only uses captured, completed wars for attack reliability: missing attacks, stars and town hall of attacked bases. Historic player-level attacks are not available from the regular public war log. Until completed snapshots exist, reliability remains **unknown** (not zero). The public API does not provide player online status or last-online time or Clan Games individual progress.

## 0.3.0: главное меню и навигация

`/menu` открывает штаб: **Войны · Состав и готовность · Рейтинги · Игроки · Мои аккаунты · Жизнь клана**. Руководству доступен отдельный кабинет. Во всех разделах есть возврат; из карточки игрока — на исходную страницу списка. Профили, герои, снаряжение, донат, изменения развития, составы и история листаются кнопками. Пустые категории объясняют, почему списка нет.

Бот редактирует один текущий экран пользователя вместо отправки нового на каждом переходе. Меню в группе принадлежит вызвавшему его пользователю; другим нужно открыть своё `/menu`. Кнопки действуют 30 минут, привязаны к владельцу, чату, сообщению и версии экрана. После перехода, рестарта или истечения срока старую кнопку нужно заменить новым `/menu`. Голоса в опубликованном опросе работают до его срока, включая после рестарта. Повторные Telegram update и двойные нажатия не выполняют действие дважды в текущем процессе.

Все экраны используют экранированный HTML, включая ники с `<`, `&`, `_`, `*`, скобками и emoji. Ошибка `Message is not modified` не закрывает меню; при удалённом сообщении создаётся один новый экран. Приветствия при вступлении варьируются без немедленного повтора фразы, имена безопасно форматируются. Синхронизация CoC-ников для обычных участников остаётся ежедневной в 09:00 Europe/Berlin; нужны права Manage Tags, админские звания Telegram не перезаписываются.

## Профили, привязки и права

`/bind` показывает свободные аккаунты из состава клана; у тега один подтверждённый владелец. Каждый аккаунт, включая твинков, подтверждается игровым **API Token**, не ключом разработчика. `/profile` и `/accounts` открывают общий список с никами, TH, опытом, лигой, званием, донатом и военной статистикой. Основной аккаунт и удаление отдельной привязки доступны кнопками; удаление требует подтверждения. `/primary #TAG`, `/unlink #TAG` и `/unbind confirm` остаются доступны.

Права `/staff`, `/captain`, `/setweight`, `/lastseen` и `/adminunlink` даёт роль `leader` или `coLeader` на любом подтверждённом аккаунте, который сейчас находится в клане. Права заново проверяются при действии; администрирование Telegram само по себе их не даёт. Бот не кикает из CoC, не повышает и не раздаёт медали автоматически. Существующая проверка привязки при вступлении в Telegram-группу сохранена.

`/progress`: развитие своего аккаунта за 7/30 дней или всю историю. Снимки `/data/player_progress.db` содержат публичные поля, для сравнения нужны минимум два разных дня. Герои строителя показываются отдельно в полном списке; на военную оценку влияют герои основной деревни.

## Состав и готовность к конкретной войне

1. Руководитель в личке открывает `/lineup` → новый сбор КВ или ЛВК. Для КВ выбирает 5–50 игроков с шагом 5; ЛВК фиксирована на 15.
2. Вводит название, например «КВ · пятница 20:00» или «ЛВК · раунд 4». Новый сбор закрывает предыдущий сбор **того же режима** и начинает ответы заново. Срок сбора — 72 часа. Название обозначает событие, но бот не запускает войну и не привязывает её автоматически к API-раунду.
3. Участники в личке используют `/ready`, выбирают сбор и отвечают за каждый свой аккаунт: **готов / не смогу / герои улучшаются**. Владелец привязки и наличие аккаунта в клане проверяются. После перепривязки старый ответ другого владельца не учитывается.
4. Капитан видит рекомендации, выбирает игроков, листает состав и публикует его. Ответ «готов» не отменяет красную отметку CoC; неизвестное игровое согласие и ручная неактивность также остаются ограничениями.
5. Перед публикацией проверяются точный размер, актуальный допуск и отрицательные ответы готовности. Игрок без ответа отмечается ❔ и может быть включён решением капитана. Если состав или ответы изменились после просмотра, экран сначала обновляется. Правки уже опубликованного состава редактируют исходное сообщение группы.

Черновики составов, ответы, версии и состояние публикации сохраняются в `war_plans`/`war_readiness` внутри `/data/bindings.db`. Незавершённый ввод названия и обычные экраны хранятся в памяти. Закрытые сборы сохраняются в базе, но отдельного браузера архивных сборов пока нет.

## Рейтинг и правила отбора

`/rating war` и `/rating cwl` показывают весь клан. Нажатие на ник раскрывает историю и вклад каждого компонента: значение × вес = вклад в балл. Высокое место само по себе не отменяет отказ от участия. КВ учитывает относительную прокачку среди одинаковых TH, а ЛВК сильнее учитывает саму ратушу.

| Компонент | КВ | ЛВК |
| --- | ---: | ---: |
| Сила | 20% | 55% |
| Дисциплина атак | 35% | 20% |
| Качество атак с учётом TH цели | 35% | 20% |
| Звание CoC | 10% | 5% |

Прокачка среди одинаковых TH: **55% герои основной деревни, 20% снаряжение, 15% опыт, 10% лига**. Недоступные признаки исключаются с перенормировкой, без сверстников оценка нейтральная. Поддерживаются числовые ступени современных лиг и Legend I/II/III. Звание — небольшой бонус доверия: базовые индексы member 50, elder 55, coLeader 60, leader 65. Поэтому при стандартных весах лидер получает относительно участника лишь +1.5 балла КВ или +0.75 ЛВК.

Сила ЛВК = 80% абсолютной силы TH + 20% относительной прокачки. Абсолютная сила — эвристика `100 × (TH / max(18, максимальная TH клана))³`, не скрытый боевой вес Supercell. Опыт не измеряет оборону, лига не доказывает качество атак. Уровни зданий, стен и ловушек, онлайн, последний вход и индивидуальные очки Игр кланов API не передаёт.

Красная отметка CoC исключает из рекомендуемого состава обоих режимов. Пропуск раунда ЛВК теперь даёт предупреждение **«уточнить причину»**, без автоматического запрета до конца сезона. Три полностью пропущенные назначенные войны подряд дают рекомендацию проверить дисциплину. Последний вход можно отметить вручную `/lastseen #TAG 3` или очистить `/lastseen #TAG clear`; 48+ часов создают отдельный резерв. Малые выборки атак сглаживаются к нейтральной оценке.

`/setweight war quality 40` и `/setweight cwl quality 45` меняют веса с сохранением суммы 100%. Пользовательские настройки остаются после обновления. `/hall` показывает несколько отдельных топов; `/donate` — весь доступный клан по донату сезона.

## ЛВК, история и напоминания

`/cwl` содержит таблицу и **семь кнопок раундов**. Номера берутся из группы CWL: недоступный раунд 2 не превращает раунд 3 во второй. Место рассчитывается по звёздам атак + 10 за каждую завершённую победу, затем суммарному разрушению; полный паритет даёт общее место. При неполных данных место предварительное. Подготовка и ничья не дают бонуса. Это локальный расчёт, не отдельный официальный endpoint мест.

`/history` открывает последние сохранённые завершённые войны: счёт, атаки каждого участника, TH целей и неиспользованные атаки. История ограничена наблюдениями бота; он не восстанавливает недоступные старые атаки. Даты — Europe/Berlin с учётом летнего времени.

Напоминания включают вторую неиспользованную атаку КВ и группируют твинков под одним упоминанием владельца. Два этапа на войну: в настроенном окне до окончания и в последние 30 минут. Проверка идёт с `war_reminder_interval_minutes`, поэтому при редком интервале этап может быть пропущен. Таблица `war_reminders` предотвращает повторы после рестарта и не мешает напомнить о новой войне.

Послевоенные сообщения сохраняют пять вариантов для победы, ничьей и поражения. Первая проверка помечает старые результаты без рассылки, последующие — публикуют новые. Опция `war_results_enabled`, проверка каждые 3 минуты; бэкенд сохраняет снимки примерно каждые 5 минут. Войны старше 12 часов не анонсируются.

## Голосования и доставка сообщений

Руководитель создаёт `/poll` в личке: вопрос до 300 символов → 2–10 различных ответов до 80 символов → срок 1 минута–30 дней (`30м`, `2ч`, `3д`) → предпросмотр → публикация. Варианты можно добавлять, последний — удалять, срок — менять до публикации. «Жизнь клана → Голосования» открывает последние 100 опубликованных опросов и результаты постранично.

Один изменяемый голос на Telegram-аккаунт до срока; твинковые привязки не дают дополнительные голоса. Голоса принимаются только из исходного сообщения нужной группы. `clan_polls`/`clan_votes` в `/data/bindings.db` переживают рестарт. Итоги обновляют исходное сообщение и отправляются отдельным сообщением, включая ничью и отсутствие голосов. Проверка каждые 30 секунд, первая через 5 секунд после запуска. Просроченные опросы обрабатываются после возвращения бота в сеть.

Перед новой отправкой результата, напоминания или состава резервируется запись в SQLite. Это предотвращает повтор при неопределённом сетевом исходе. У Telegram нет ключа идемпотентности отправки: если ответ потерялся после принятия сообщения, бот **не отправляет его автоматически повторно**. Поэтому отдельное уведомление иногда может не прийти. Результат голосования остаётся в исходном сообщении и доступен в списке. Неопределённая публикация состава блокирует повторную отправку; капитану показывается просьба проверить группу. При явном отклонении Telegram черновик можно исправить и повторить. Изменение существующего сообщения допускает безопасный повтор.

## Обновление и проверка

Требуется слияние в **Beerlogger01/main**, успешная сборка и публикация образа **0.3.0** в GHCR, затем обновление аддона в Home Assistant. PR и ветка сами по себе не обновляют работающего бота. База привязок сохраняется; новые таблицы добавляются автоматически. Рекомендуется обычная резервная копия аддона перед обновлением.

Автоматическая проверка использует настоящий `python-telegram-bot Application` и те же обработчики, с подставными транспортами Telegram/CoC. Проверяются меню, переходы, страницы, права, пустые данные, специальные символы, устаревшие кнопки, повторная доставка, публикации и рестарты хранилищ. Живой бот и настоящая группа для этих тестов не используются. Подробная матрица — `docs/interface-qa-0.3.0.md` в репозитории.
